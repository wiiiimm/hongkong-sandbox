## Reproduce and resume

Use the existing Python environment with NumPy/Shapely and Node 24/Playwright. Local viewer port is 4176. Claim the exact canonical source UIDs using the shared Neon reservations and run long commands through `reservations.py run`. The adapters currently use explicitly named local `/tmp/astra-…-lease.json` receipts; create fresh valid receipts on a new device rather than copying an expired claim.

1. `acquire.py`, `pack.py`, `support.mjs`: bounded four-part LOHAS source/triangle proof.
2. `terrain.py`, `terrain_check.py`, `terrain_patch.py`: reuse native terrain and stage the bounded correction. The patch adapter uses the already reviewed multi-primitive decoder; it does not alter shared helpers.
3. `discover.py`: queue source footprints that may provide omitted support. Adjacency only nominates acquisition; it never approves structure.
4. `bulk_acquire.py`: acquire the independent 69-part subset with four workers, complete directory accounting and a 150 MB cumulative transfer cap; then run the existing matcher/packer without a SQLite writer.
5. `verify_acquisition.py`: unchanged source verifier against both batches.
6. `prepare_support_batch.py`, `review.mjs`, `decisions.py`, `coverage.py`: versioned full accounting and exact dependency/coverage checks.
7. `bulk-browser.mjs`: reserved 58-part camera-safe normal/isolated review with the staged LOHAS terrain. `--retry` preserves original measurements and broadens the camera search only for unclear views. Review exported images and record specific observations in `visual-observations.json`.
8. `author_decisions.py` binds those explicit observations to image/input hashes and propagates unresolved native-support holds. `prepare_approved.py --lease-file <receipt>` prepares the accepted closure, terrain plan and guard under current reservations; it does not publish.

`combined-support.json` is a local 21 MB raw report; restore it from its adjacent `.json.gz` when needed. Approximately 215 MB of raw source/staged caches are ignored in Git; `cache-handoff.json` lists the paths for the next authorised R2 working-material checkpoint. Compact candidates and provenance are retained. No R2 upload, runtime publication, native geometry change, height multiplier or source replacement was performed by this pass.
